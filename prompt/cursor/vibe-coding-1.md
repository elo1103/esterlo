Build a modern SaaS-style web application prototype called:

"Decision-Centered Capacity Planning"

Purpose:
This is a fictional portfolio demonstration for an automation consultant working with architectural manufacturing companies.

IMPORTANT:

* Use completely fictional data.
* Do not reference any real company, project, customer, employee, ERP system, SharePoint site, Power BI report, SQL schema, or proprietary workflow.
* The application should demonstrate decision-support concepts rather than simple reporting.

Technology:

* Javascript/css/html
* Static JSON data only
* No backend
* No authentication
* Only front end UI for demo purpose

Design Style:

* Executive dashboard
* Modern B2B SaaS
* Clean, minimal, professional
* Mimic Apple's design and website style
* Similar quality to Linear, Stripe Dashboard, Vercel, Notion Analytics

Page Structure:

================================================
SECTION 1 — Executive Summary
=============================

Show KPI cards:

* Active Projects
* Total Estimated Hours
* Total Actual Hours
* Capacity Utilization %
* Projects At Risk

Include a short executive summary:

"This week's workload exceeds available capacity by 12%. Two projects require management attention."

================================================
SECTION 2 — Capacity Risk Overview
==================================

Create a chart showing:

* Estimated Hours
* Actual Hours

for multiple projects.

Use fictional projects:

* Project Atlas
* Project Nova
* Project Orion
* Project Horizon
* Project Summit

Highlight projects exceeding planned capacity.

================================================
SECTION 3 — Decision Support Table
==================================

Columns:

Project Name
Revenue Impact
Estimated Hours
Actual Hours
Variance %
Due Date
Risk Score
Status

Risk Score should be calculated using fake business logic.

Status examples:

* Healthy
* Watch
* High Risk

================================================
SECTION 4 — Why This Project Is At Risk
=======================================

When selecting a project, display:

Capacity Risk Factors

Examples:

* Actual labor hours exceed estimate by 28%
* Installation date is approaching
* Shop workload exceeds department capacity
* Material delivery delay detected

Use fictional explanations.

================================================
SECTION 5 — Recommended Management Actions
==========================================

This section is critical.

Display recommendations such as:

Recommendation:
Delay Project Nova by one week.

Reason:

* Lowest revenue impact
* Highest labor variance
* Reduces department overload by 15%

Alternative Recommendation:
Allocate two additional fabricators.

Expected Outcome:

* Capacity utilization reduced from 112% to 98%

================================================
SECTION 6 — Decision Knowledge Capture
======================================

Display a timeline showing:

Decision
Reason
Outcome

Example:

Decision:
Delay Project Nova

Reason:
Fabrication workload exceeded available labor.

Outcome:
Prevented overtime and avoided delay on Project Atlas.

Purpose:
Demonstrate organizational knowledge retention and decision transparency.

================================================

Overall Goal:

This application should feel less like a reporting dashboard and more like a management decision-support system.

The central message is:

"The problem is not scheduling.

The problem is making operational decision-making visible, repeatable, and transferable."
